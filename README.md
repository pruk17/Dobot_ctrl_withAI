## 1. ภาพรวม

โปรแกรมเดียวมี 2 แท็บ ตามข้อกำหนดการแข่งขัน

**โหมดที่ 1 Training**
เก็บภาพจากกล้อง Webcam สร้างชุดข้อมูล ติดป้ายกำกับ (Data Labeling) ภายในโปรแกรม
เลือกโมเดล YOLOv8 และขนาดภาพ แล้วฝึกสอนโมเดล ผลลัพธ์ถูกบันทึกที่ `dataset/model/best.pt`

**โหมดที่ 2 Deployment และ Inference**
โหลดโมเดลที่ฝึกสอนแล้ว แสดงภาพกล้องแบบ real-time กดปุ่มหรือคีย์ `S` เพื่อตรวจจับ
นับจำนวนวัตถุแต่ละคลาส ส่งผลไปยังหุ่นยนต์ผ่าน TCP/IP แล้วเข้าสถานะรอจนได้รับ `Done`

## 3. การติดตั้ง

รันทุกคำสั่งจากโฟลเดอร์ของโปรเจกต์

**สร้าง virtual environment**

```
python -m venv venv
```

ไม่จำเป็นต้อง activate ให้เรียก python ใน venv ตรง ๆ ตามคำสั่งด้านล่าง เพราะ PowerShell
มักบล็อกสคริปต์ activate ด้วย ExecutionPolicy

**ติดตั้ง PyTorch**

เลือกอย่างใดอย่างหนึ่ง ถ้าเครื่องไม่มีการ์ดจอ NVIDIA ให้ใช้แบบ CPU ซึ่งมีขนาดเล็กกว่ามาก

```
venv/Scripts/python.exe -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
```

ถ้ามีการ์ดจอ NVIDIA และต้องการใช้ GPU

```
venv/Scripts/python.exe -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
```

**ติดตั้งไลบรารีที่เหลือ**

```
venv/Scripts/python.exe -m pip install -r requirements.txt
```

## 4. การเตรียมพร้อมก่อนวันแข่งขัน

วันแข่งขันห้ามใช้อินเทอร์เน็ต ต้องเตรียมให้ครบทุกข้อล่วงหน้า

**ดาวน์โหลดไฟล์น้ำหนักโมเดลตั้งต้น**

```
venv/Scripts/python.exe -c "from ultralytics import YOLO; YOLO('yolov8n.pt'); print('cached ok')"
```

ไฟล์ `yolov8n.pt` จะถูกบันทึกไว้ในโฟลเดอร์ที่รันคำสั่ง คือข้าง ๆ `main_app.py` ห้ามลบ
ถ้าจะใช้รุ่น s ด้วย ให้รันซ้ำโดยเปลี่ยนชื่อไฟล์เป็น `yolov8s.pt`

**ปิดการเชื่อมต่อออกนอกเครื่องของ ultralytics**

```
venv/Scripts/yolo.exe settings sync=False
```

ป้องกันไม่ให้ไลบรารีพยายามส่งสถิติการใช้งานออกไปแล้วค้างรอ timeout ตอนไม่มีเน็ต

**ล็อกเวอร์ชันไลบรารี**

```
venv/Scripts/python.exe -m pip freeze > requirements.lock.txt
```

**ซ้อมทั้งระบบอย่างน้อย 1 รอบเต็ม**
ตั้งแต่ถ่ายภาพ ติดป้าย ฝึกสอน จนถึงเชื่อมต่อหุ่นยนต์และส่งผลตรวจจับ

## 6. โหมดที่ 1 Training

**ขั้นที่ 1 เลือกกล้อง**
กดปุ่ม ค้นหากล้อง โปรแกรมจะไล่สแกน index 0 ถึง 5 ใช้เวลาราว 10 ถึง 30 วินาที
โดยปกติ index 0 คือกล้อง built-in ส่วนกล้อง USB ภายนอกมักอยู่ที่ index 1 ขึ้นไป
โปรแกรมจะเลือก index สูงสุดที่พบให้อัตโนมัติ จากนั้นกด เปิดกล้อง

**ขั้นที่ 2 เพิ่มคลาส**
พิมพ์ชื่อคลาสในช่องด้านล่างซ้าย เช่น `circle` แล้วกด เพิ่มคลาส ทำซ้ำจนครบทุกสัญลักษณ์
ต้องมีอย่างน้อย 1 คลาสก่อน ไม่เช่นนั้นจะถ่ายภาพไม่ได้

**ขั้นที่ 3 เก็บภาพ**
เลือกคลาสในช่อง คลาสที่จะบันทึกเมื่อถ่ายภาพ แล้วกด ถ่ายภาพ
ควรเก็บภาพหลายมุม หลายระยะ และหลายสภาพแสง เพื่อความแม่นยำของโมเดล
หรือใช้ปุ่ม นำเข้ารูปภาพจากไฟล์ ถ้ามีภาพเตรียมไว้แล้ว

**ขั้นที่ 4 ติดป้ายกำกับ**
เลือกคลาสสำหรับวาดกรอบ แล้วลากเมาส์ล้อมวัตถุบนภาพทางขวา
วาดได้หลายกรอบต่อภาพ และลบกรอบที่เลือกได้จากรายการด้านขวา
กด บันทึก Label ทุกครั้งก่อนกด ถัดไป
ถ้ามีชุดข้อมูลที่ติดป้ายจากเครื่องมือภายนอกอยู่แล้ว ใช้ปุ่ม นำเข้าชุดข้อมูลที่ติดป้ายแล้ว แทนได้

**ขั้นที่ 5 ตั้งค่าการเพิ่มข้อมูล**
กดปุ่ม ตั้งค่าการเพิ่มข้อมูล ดูรายละเอียดในหัวข้อถัดไป ข้ามได้ถ้าใช้ค่าที่ตั้งมาให้

**ขั้นที่ 6 แบ่งชุดข้อมูล**
กดปุ่ม 1) แบ่งชุด Train/Val (80/20)

**ขั้นที่ 7 ฝึกสอน**
ตั้งค่าโมเดล จำนวน epochs และ image size แล้วกดปุ่ม 2) เริ่มฝึกสอนโมเดล
ความคืบหน้าแบบละเอียดแสดงในหน้าต่าง Terminal ที่รันโปรแกรม ส่วนกล่อง log ในโปรแกรม
แสดงเฉพาะสถานะเริ่มและจบ เมื่อเสร็จ โมเดลจะถูกคัดลอกไปที่ `dataset/model/best.pt`

### การเพิ่มข้อมูล (Data Augmentation)

การเพิ่มข้อมูลคือการสร้างภาพหลากหลายรูปแบบจากภาพที่ถ่ายไว้ เพื่อให้โมเดลทนต่อการวางมุมต่างกัน
แสงต่างกัน และสีต่างกัน โดยไม่ต้องถ่ายภาพเพิ่มเอง โปรแกรมนี้ใช้สองวิธีร่วมกัน

| | แบบ online | แบบ offline |
|---|---|---|
| ใครทำ | ultralytics ระหว่างเทรน | โปรแกรมเรา ก่อนเริ่มเทรน |
| เขียนไฟล์เพิ่ม | ไม่ | เขียน ชื่อไฟล์มีคำว่า `__aug` |
| ความหลากหลาย | สุ่มใหม่ทุก epoch | คงที่ตามไฟล์ที่สร้าง |
| ใช้กับ | หมุน ย่อขยาย เลื่อน สี แสง พลิก | ขาวดำ เบลอ และการพลิกเฉพาะบางคลาส |

ไฟล์ที่สร้างแบบ offline จะถูกลบและสร้างใหม่ทุกครั้งที่กดเทรนหรือกดแบ่งชุดข้อมูล
จึงไม่มีการสะสมทับกัน และไม่แสดงในหน้าติดป้ายกำกับ ค่าที่ตั้งไว้ถูกบันทึกในไฟล์
`dataset/augment.json`

**การพลิกซ้ายขวาแบบเลือกรายคลาส**

ในหน้าตั้งค่าจะมีรายการคลาสให้ติ๊ก ติ๊กไว้หมายถึงอนุญาตให้พลิกภาพของคลาสนั้นเป็นภาพกระจก
ให้เอาติ๊กออกเฉพาะคลาสที่พลิกแล้วกลายเป็นหน้าตาของอีกคลาสหนึ่ง เช่นเมื่อมีทั้ง `arrow_left`
และ `arrow_right` หรือมีทั้งตัว b และตัว d เพราะภาพที่ถูกพลิกจะยังติดป้ายคลาสเดิม
กลายเป็นการสอนโมเดลด้วยข้อมูลที่ขัดแย้งกันเอง ส่วนรูปทรงสมมาตรอย่างวงกลม สี่เหลี่ยม
สามเหลี่ยมหน้าจั่ว ดาว ติ๊กไว้ได้ตามปกติ

YOLO ควบคุมการพลิกที่ระดับภาพ ไม่ใช่ระดับคลาส และหนึ่งภาพมีได้หลายคลาส โปรแกรมจึงเลือกวิธีให้เอง

- ทุกคลาสอนุญาต ใช้ `fliplr` ของ YOLO ซึ่งสุ่มใหม่ทุก epoch และไม่กินพื้นที่ดิสก์
- มีบางคลาสห้ามพลิก บังคับ `fliplr` เป็น 0 แล้วสร้างไฟล์ภาพพลิกไว้ล่วงหน้าเฉพาะภาพที่ทุกคลาสในภาพนั้นอนุญาต
- ทุกคลาสห้ามพลิก ไม่พลิกเลย

**ขาวดำและเบลอ**

ทั้งสองอย่างนี้ ultralytics มีให้ผ่านแพ็กเกจเสริม albumentations เท่านั้น และตั้งค่าความน่าจะเป็น
ไว้ตายตัวที่ 1 เปอร์เซ็นต์ซึ่งแทบไม่มีผล โปรแกรมนี้จึงเขียนเองด้วย OpenCV ไม่ต้องติดตั้งอะไรเพิ่ม

ขาวดำใช้เมื่อสัญลักษณ์อาจมาในหลายสี เพื่อบังคับให้โมเดลตัดสินจากรูปทรง ห้ามเปิดถ้าคลาสต่างกัน
แยกด้วยสีเป็นหลัก เบลอจำลองกล้อง USB ที่ไล่โฟกัสไม่ทันหรือมือสั่นตอนวางชิ้นงาน แนะนำระดับ 3 ถึง 5
ถ้าเบลอแรงเกินไปโมเดลจะเห็นเป็นก้อนเบลอแล้วตรวจจับผิดพลาดง่ายขึ้น

**ค่าเริ่มต้นที่ตั้งมาให้**

| ค่า | ตั้งไว้ | เหตุผล |
|---|---|---|
| หมุนภาพสุ่ม | 180 องศา | แผ่นถูกวางมุมไหนก็ได้บนถาด |
| พลิกซ้ายขวา | 0.5 | ปลอดภัยเมื่อไม่มีคู่สัญลักษณ์ที่เป็นภาพสะท้อนกัน |
| พลิกบนล่าง | 0.5 | กล้องมองจากด้านบน แผ่นอาจกลับหัวได้ |
| เปลี่ยนเฉดสี | 0.5 | ให้เจอได้ทุกสี ใช้แทนการแปลงเป็นขาวดำ |
| เปลี่ยนความอิ่มสี | 0.9 | เพิ่มโอกาสเห็นภาพที่สีจางจนเกือบขาวดำ |
| เปลี่ยนความสว่าง | 0.4 | แสงห้องแข่งต่างจากห้องซ้อม |
| ย่อขยาย | 0.5 | ระยะกล้องกับชิ้นงานเปลี่ยนได้ |
| เลื่อนตำแหน่ง | 0.1 | ชิ้นงานวางไม่ตรงกลางเฟรม |
| ต่อ 4 ภาพเป็นภาพเดียว | 1.0 | ช่วยมากเมื่อมีภาพน้อย ปิดเองใน 10 epoch สุดท้าย |
| สำเนาขาวดำ และ สำเนาเบลอ | ปิด | เปิดเมื่อจำเป็น เพราะทำให้ชุดข้อมูลโตขึ้นเท่าตัว |

## 7. โหมดที่ 2 Deployment และ Inference

**ขั้นที่ 1** กดปุ่ม โหลดโมเดล แล้วเลือกไฟล์ `dataset/model/best.pt`

**ขั้นที่ 2** เลือกกล้องและกด เปิดกล้อง

**ขั้นที่ 3** กรอก IP Address และ Port ของหุ่นยนต์ แล้วกด เชื่อมต่อ
โปรแกรมจะส่ง `Ready` และรอ `ACK` ถ้าไม่ได้รับจะส่งซ้ำอัตโนมัติสูงสุด 5 ครั้ง

**ขั้นที่ 4** ตั้งค่า รอ Done ไม่เกิน ให้นานกว่าเวลาที่หุ่นยนต์ใช้จัดวางจริง ค่าเริ่มต้นคือ 180 วินาที

**ขั้นที่ 5** เมื่อสถานะขึ้นว่า พร้อมทำงาน ให้กดปุ่ม เริ่มการตรวจจับ หรือกดคีย์ `S`
รองรับทั้งตัวพิมพ์เล็กและตัวพิมพ์ใหญ่ และจะไม่ทำงานขณะที่เคอร์เซอร์อยู่ในช่องกรอกข้อความ

**ขั้นที่ 6** โปรแกรมจะจับภาพ ประมวลผล นับจำนวนวัตถุแต่ละคลาส แสดงผลทั้งแบบอ่านง่าย
และแบบข้อความที่ส่งจริง จากนั้นเข้าสถานะรอจนกว่าจะได้รับ `Done`

### สถานะที่แสดงและความหมาย

| สี | สถานะ | ความหมาย |
|---|---|---|
| เทา | ยังไม่ได้เชื่อมต่อ | ยังไม่มี socket |
| ส้ม | เชื่อมต่อแล้ว | ต่อ TCP ได้ แต่ยังไม่ได้รับ ACK |
| เขียว | พร้อมทำงาน | ได้รับ ACK แล้ว กดตรวจจับได้ |
| ส้ม | รอ Done | ส่งผลไปแล้ว หุ่นยนต์กำลังทำงาน |
| แดง | หมดเวลารอ Done | เกินเวลาที่ตั้งไว้ ต้องกดปุ่ม ยกเลิกการรอ |

เมื่อหมดเวลารอ โปรแกรมจะไม่ปลดล็อกตัวเองกลับไปสถานะพร้อม เพราะถ้าปลดล็อกแล้ว
ผู้ใช้กดตรวจจับรอบใหม่ ข้อความ `Done` ของรอบเก่าที่มาถึงทีหลังจะถูกอ่านเป็นคำตอบของรอบใหม่
ทำให้การสื่อสารสองฝั่งเหลื่อมกันไปตลอดทั้งการแข่งขัน
ปุ่ม ยกเลิกการรอ Done จะล้างข้อมูลค้างในสายทิ้งก่อนกลับสู่สถานะพร้อม จึงปลอดภัย

## 8. โปรโตคอลการสื่อสาร

โปรแกรม AI ทำหน้าที่เป็น TCP Client หุ่นยนต์ Dobot MG400 ทำหน้าที่เป็น TCP Server
ทุกข้อความที่ส่งออกจะต่อท้ายด้วย `\n`

| จังหวะ | โปรแกรมส่ง | หุ่นยนต์ต้องตอบ |
|---|---|---|
| หลังเชื่อมต่อสำเร็จ ทำครั้งเดียว | `Ready` ส่งซ้ำถ้าไม่ได้รับ ACK | `ACK` |
| ทุกครั้งที่กดตรวจจับ | `circle,3,square,2` หรือ `none` | `Done` |

ฝั่งรับข้อมูลใช้ buffer ภายใน จึงรองรับทั้งกรณีที่ข้อความถูกแบ่งมาหลายแพ็กเก็ต
กรณีหลายข้อความมาในแพ็กเก็ตเดียว และกรณีที่เซิร์ฟเวอร์ไม่ได้ปิดท้ายข้อความด้วยขึ้นบรรทัดใหม่

### ค่า timeout

| ค่า | ค่าเริ่มต้น | ใช้ทำอะไร |
|---|---|---|
| connect_timeout | 5 วินาที | เชื่อมต่อ TCP |
| ack_timeout | 5 วินาที | รอ `ACK` ต่อการส่ง `Ready` หนึ่งครั้ง |
| done_timeout | 180 วินาที | รอ `Done` ปรับได้จากหน้าโปรแกรม |
| ready_retries | 5 ครั้ง | จำนวนครั้งสูงสุดที่ส่ง `Ready` ซ้ำ |

## 9. การทดสอบโดยไม่มีหุ่นยนต์จริง

ใช้สคริปต์จำลองที่แนบมา เปิดค้างไว้อีกหน้าต่างหนึ่ง

```
venv/Scripts/python.exe mock_robot_server.py --port 29999 --work-seconds 2
```

แล้วในโปรแกรมให้ใส่ IP เป็น `127.0.0.1` และ Port เป็น `29999`
สคริปต์รับการเชื่อมต่อใหม่ได้เรื่อย ๆ ไม่ต้องปิดเปิดใหม่ทุกครั้ง หยุดด้วย Ctrl+C

ทดสอบกรณีหุ่นยนต์ทำงานนานกว่า timeout ได้ด้วยการตั้ง `--work-seconds`
ให้มากกว่าค่า รอ Done ไม่เกิน ที่ตั้งไว้ในโปรแกรม

ใช้โปรแกรม Hercules แทนได้เช่นกัน โดยตั้งให้ตอบ `ACK` เมื่อรับ `Ready`
และตอบ `Done` เมื่อรับผลตรวจจับ

## 11. การแก้ปัญหาที่พบบ่อย

**กดถ่ายภาพแล้วขึ้นว่ายังไม่ได้เลือกคลาส**
ต้องเพิ่มคลาสก่อน พิมพ์ชื่อคลาสในช่องด้านล่างซ้ายแล้วกด เพิ่มคลาส
จากนั้นเลือกคลาสนั้นในช่อง คลาสที่จะบันทึกเมื่อถ่ายภาพ

**ค้นหากล้องแล้วไม่พบ**
กล้องหนึ่งตัวเปิดได้ทีละโปรแกรมเท่านั้น ถ้ามีหน้าต่างอื่นหรืออีกแท็บหนึ่งเปิดกล้องค้างไว้
จะสแกนไม่เจอ ให้กด ปิดกล้อง ก่อนแล้วลองใหม่
ข้อความสีแดงของ OpenCV ที่ขึ้นระหว่างสแกนเป็นเรื่องปกติ ไม่ใช่ error

**เชื่อมต่อ TCP ได้แต่ไม่ได้รับ ACK**
ตรวจสอบว่าใส่พอร์ตถูกต้อง พอร์ต 29999 เป็นพอร์ต Dashboard ของ Dobot
ซึ่งจะตอบกลับเป็นรหัสคำสั่งของ Dobot ไม่ใช่ `ACK`
ต้องใช้พอร์ตของ TCP server ที่เขียนไว้ในโปรแกรมฝั่งหุ่นยนต์

**ฝึกสอนแล้วค้างนาน หรือขึ้นว่าดาวน์โหลดไม่ได้**
ไฟล์ `yolov8n.pt` ยังไม่ถูกดาวน์โหลด ให้กลับไปทำตามหัวข้อที่ 4

**ตัวหนังสือหรือหน้าต่างมีขนาดผิดปกติ**
โปรแกรมประกาศตัวเป็น DPI aware จึงวาดที่ความละเอียดจริงของจอ
ถ้าต้องการตัวหนังสือใหญ่ขึ้น ให้แก้ค่าฟอนต์ในไฟล์ `ui_theme.py`
ตัวเลขเป็นค่าลบซึ่งหมายถึงหน่วยพิกเซล เช่นเปลี่ยนจาก `-13` เป็น `-15`

## 12. ข้อจำกัดที่ทราบ

- ปุ่มตรวจจับกดได้ต่อเมื่อเชื่อมต่อหุ่นยนต์และได้รับ `ACK` แล้วเท่านั้น ตามข้อกำหนดการแข่งขัน
  จึงทดสอบ inference เดี่ยว ๆ โดยไม่มีหุ่นยนต์ไม่ได้ ให้ใช้ `mock_robot_server.py` แทน
- การ inference ทำงานบน thread หลัก หน้าจอจะหยุดนิ่งเสี้ยววินาทีระหว่างประมวลผล
- ผลการตรวจจับแสดงเป็นตัวเลข ยังไม่ได้วาดกรอบผลลัพธ์ทับลงบนภาพ
- การนำเข้าชุดข้อมูลที่ติดป้ายจากภายนอกยังไม่ได้แปลง class id ให้ตรงกับลำดับใน
  `classes.txt` ปัจจุบัน ถ้าลำดับคลาสของต้นทางไม่ตรงกัน label จะชี้ผิดคลาส
- เมนูเลือกโมเดลมีเฉพาะตระกูล YOLOv8 หากต้องการ RT-DETR ให้แก้ `train_tab.py`
  และ `infer_tab.py` โดยเปลี่ยนจาก `YOLO(...)` เป็น `RTDETR(...)`
