# โปรแกรม AI ตรวจจับวัตถุ + สื่อสารกับ Dobot MG400 ผ่าน TCP/IP
สำหรับ: **BRICS Skills Competition Thailand 2026** — การเขียนโปรแกรมประยุกต์ควบคุมหุ่นยนต์และปัญญาประดิษฐ์
(ชุดฝึกปฏิบัติการ Universal Training Platform (UTP) + Dobot MG400)

โปรแกรมนี้เขียนด้วย **Python + Tkinter (GUI)** และ **ultralytics YOLOv8** ครอบคลุมข้อกำหนดทั้ง 2 โหมดตามเอกสารการแข่งขัน:

- **โหมดที่ 1 — Model Training**: ถ่าย/นำเข้าภาพจากกล้อง Webcam, ติดป้ายกำกับ (Data Labeling) ในโปรแกรม, เลือกโมเดล (YOLOv8), ฝึกสอนโมเดล
- **โหมดที่ 2 — Model Deployment & Inference**: โหลดโมเดลที่ฝึกสอนแล้ว, แสดงภาพกล้อง Real-time, ปุ่ม Detect (คีย์ลัด `S`), นับจำนวนวัตถุแต่ละคลาส, ส่งผลลัพธ์ไปหุ่นยนต์ผ่าน TCP/IP และรอ `Done`

---

## 1. การติดตั้ง (ทำล่วงหน้า ก่อนวันแข่งขัน — เพราะห้ามใช้อินเทอร์เน็ตระหว่างแข่งขัน)

```bash
pip install -r requirements.txt
```

> **สำคัญ**: หากเลือกใช้โมเดลตั้งต้นแบบ pretrained (`yolov8n.pt` / `yolov8s.pt`) ultralytics จะพยายาม
> ดาวน์โหลดไฟล์น้ำหนักโมเดลจากอินเทอร์เน็ตในการรันครั้งแรก ให้ **รันโปรแกรมและกดฝึกสอนอย่างน้อย 1 ครั้ง
> ระหว่างวันเตรียมความพร้อม (มีอินเทอร์เน็ต)** เพื่อให้ไฟล์น้ำหนักถูกดาวน์โหลดและแคชไว้ในเครื่องก่อน
> ในวันแข่งขันจริงจะได้ไม่ต้องพึ่งอินเทอร์เน็ต หรือเลือกตัวเลือก "ฝึกใหม่ทั้งหมด ไม่ใช้ pretrained" แทนได้

## 2. การรันโปรแกรม

```bash
python main_app.py
```

จะเปิดหน้าต่างโปรแกรมที่มี 2 แท็บ: **โหมดที่ 1: Training** และ **โหมดที่ 2: Deployment & Inference**

---

## 3. ขั้นตอนการใช้งาน โหมดที่ 1 (Training)

1. เลือกกล้องที่ช่อง **"เลือกกล้อง"** ก่อน (กด **"ค้นหากล้อง"** เพื่อให้โปรแกรมสแกนหา index ของกล้องที่ต่ออยู่ทั้งหมด
   — โดยทั่วไป index `0` คือกล้อง Built-in ของโน้ตบุ๊ก ส่วนกล้อง USB ภายนอกมักอยู่ที่ index `1` ขึ้นไป
   ตามกติกาการแข่งขันต้องใช้กล้อง USB ภายนอก ไม่ใช่กล้อง Built-in) จากนั้นกด **"เปิดกล้อง"**
2. ช่อง **"เพิ่มคลาส"** ให้พิมพ์ชื่อคลาส เช่น `circle`, `square` แล้วกด **เพิ่มคลาส** (ทำตามจำนวนสัญลักษณ์ที่โจทย์กำหนด)
3. เลือกคลาสในช่อง **"คลาสที่จะบันทึกเมื่อถ่ายภาพ"** แล้วกด **"ถ่ายภาพ"** เพื่อเก็บภาพตัวอย่างของแต่ละคลาสให้ได้หลายมุม/หลายสภาพแสง
   (หรือใช้ **"นำเข้ารูปภาพจากไฟล์"** ถ้ามีภาพเตรียมไว้แล้ว)
4. ในกล่อง **"ติดป้ายกำกับข้อมูล"**: เลือกคลาสสำหรับวาดกรอบ แล้วลากเมาส์บนภาพเพื่อวาดกรอบล้อมวัตถุ (bounding box)
   - วาดได้หลายกรอบต่อภาพ, ลบกรอบที่เลือกได้จากลิสต์ด้านขวา
   - กด **"บันทึก Label"** ทุกครั้งหลังวาดกรอบเสร็จในแต่ละภาพ แล้วกด **"ถัดไป >"** เพื่อไปภาพถัดไป
   - (ทางเลือก) กด **"นำเข้าชุดข้อมูลที่ติดป้ายแล้ว (YOLO format)"** หากมีชุดข้อมูลที่ label ไว้แล้วจากเครื่องมือภายนอก
5. กด **"1) แบ่งชุด Train/Val อัตโนมัติ (80/20)"** เพื่อสุ่มแบ่งข้อมูลก่อนฝึกสอน
6. ตั้งค่า epochs / image size / โมเดลตั้งต้น แล้วกด **"2) เริ่มฝึกสอนโมเดล (Train)"**
   - ความคืบหน้าจะแสดงในกล่อง log ด้านล่าง
   - เมื่อเสร็จ โมเดลจะถูกคัดลอกไปไว้ที่ `dataset/model/best.pt` โดยอัตโนมัติ

## 4. ขั้นตอนการใช้งาน โหมดที่ 2 (Deployment & Inference)

1. กด **"โหลดโมเดล (.pt)"** แล้วเลือกไฟล์ `dataset/model/best.pt` (หรือโมเดลอื่นที่ฝึกสอนไว้)
2. กด **"เปิดกล้อง"** เพื่อแสดงภาพ Real-time
3. กรอก **IP Address / Port** ของแขนหุ่นยนต์ Dobot MG400 (ทำหน้าที่เป็น TCP Server) แล้วกด **"เชื่อมต่อ (Connect)"**
   - โปรแกรมจะส่ง `"Ready"` และรอรับ `"ACK"` จากหุ่นยนต์ก่อน (ทำครั้งเดียวตอนเริ่มต้น ตามข้อกำหนด)
   - สถานะจะแสดงที่ป้าย **"สถานะ: ..."**
4. เมื่อสถานะเป็น **"พร้อมทำงาน (Ready)"** ให้กดปุ่ม **"เริ่มการตรวจจับ (Detect: S)"** หรือกดปุ่ม `S` บนแป้นพิมพ์
   - โปรแกรมจะจับภาพปัจจุบัน ประมวลผล (Inference), นับจำนวนวัตถุแต่ละคลาส
   - ส่งผลลัพธ์ไปยังหุ่นยนต์เป็นข้อความ เช่น `circle,3,square,2` หรือ `none` หากไม่พบวัตถุ
   - จากนั้นเข้าสถานะรอ (**Wait State**) จนกว่าจะได้รับ `"Done"` จากหุ่นยนต์ จึงจะกลับมากดตรวจจับรอบถัดไปได้
5. กล่อง **"ประวัติการรับ-ส่งข้อมูล (Communication Log)"** จะบันทึกทุกข้อความที่ส่ง/รับ พร้อมเวลา

### การทดสอบโดยไม่มีหุ่นยนต์จริง
สามารถใช้โปรแกรมจำลอง TCP Server เช่น **Hercules** หรือเขียนสคริปต์ Python สั้น ๆ จำลอง Dobot MG400:
เปิด listen ที่พอร์ตที่กำหนด, เมื่อรับ `"Ready"` ให้ตอบ `"ACK"`, เมื่อรับผลตรวจจับ (เช่น `circle,3,square,2`) ให้หน่วงเวลาสั้น ๆ
แล้วตอบกลับ `"Done"`

## 5. โครงสร้างไฟล์

```
dobot_ai_vision/
├── main_app.py        # จุดเริ่มต้นโปรแกรม (รวม 2 แท็บ)
├── train_tab.py        # โหมดที่ 1: capture/label/train
├── infer_tab.py        # โหมดที่ 2: inference + TCP client
├── tcp_client.py        # โมดูลจัดการ Socket TCP (Ready/ACK, ผลลัพธ์/Done)

├── requirements.txt
└── dataset/             # ถูกสร้างอัตโนมัติเมื่อรันโปรแกรมครั้งแรก
    ├── images/train, images/val
    ├── labels/train, labels/val
    ├── classes.txt
    ├── data.yaml
    └── model/best.pt
```

## 6. หมายเหตุสำคัญตามกติกาการแข่งขัน

- โปรแกรมนี้เป็นโปรแกรมที่พัฒนาขึ้นเอง (ไม่ใช่โปรแกรมสำเร็จรูป) ตามข้อกำหนด "ไม่อนุญาตให้ใช้โปรแกรมสำเร็จรูปมาใช้ในการแข่งขัน"
- รองรับการเลือกโมเดลตรวจจับวัตถุ เช่น YOLO ตามที่โจทย์ระบุ (`YOLO, RT-DETR หรือโมเดลอื่น ๆ ที่เหมาะสม`)
  หากต้องการเปลี่ยนไปใช้สถาปัตยกรรมอื่น (เช่น RT-DETR) สามารถแก้ไขใน `train_tab.py`/`infer_tab.py`
  โดยเปลี่ยนจาก `YOLO(...)` เป็นคลาสโมเดลที่ต้องการจาก ultralytics (เช่น `RTDETR(...)`)
- ทำการ **ทดสอบเชื่อมต่อและฝึกซ้อมทั้งระบบล่วงหน้า** ในวันเตรียมความพร้อม เพราะวันแข่งขันจริงห้ามใช้อินเทอร์เน็ต
- ควรถ่ายภาพตัวอย่างของสัญลักษณ์แต่ละแบบให้หลากหลายมุม/แสง/ระยะ เพื่อความแม่นยำของโมเดล
